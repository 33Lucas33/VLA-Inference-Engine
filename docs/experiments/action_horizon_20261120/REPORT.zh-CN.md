# SmolVLA × LIBERO：每次预测后执行多少步动作？

2026-11-20 的单 episode 展示实验。固定公开 SmolVLA checkpoint（SHA256 `71d9563c8295284acba8fc2d5c19de000d6fe9ba58a406832af7ef3d221ed52f`）、固定 LeRobot commit `8ae2354592ec4480c38134fb75350b8e7992e0e9`、seed 1000、初态 0、256×256 双相机、`relative` 控制和 10 步 flow sampling。模型始终预测 `chunk_size=50` 步动作；只改变 `n_action_steps=1/5/10/20`，即每次预测后从队列实际执行的步数 K。

任务分别是 Spatial task 0（把黑碗放到盘子上）、Object task 0（把字母汤罐放进篮子）、Goal task 0（打开柜子中间的抽屉）。每个任务和 K 运行一个完整 episode，并录制双相机并排视频，共 12 段。每段视频左侧是外部相机，右侧是腕部相机；每执行一次动作写入一帧，另有初始帧，以 20 fps 回放。视频按仿真步回放，播放时长不是推理运行耗时。

| 黑碗放盘 | 5 | 是 | 75 | 15 | 8.41 s |
| 黑碗放盘 | 10 | 是 | 75 | 8 | 5.73 s |
| 黑碗放盘 | 20 | 是 | 75 | 4 | 4.48 s |
| 字母汤罐入篮 | 1 | 是 | 221 | 221 | 86.27 s |
| 字母汤罐入篮 | 5 | 是 | 155 | 31 | 15.57 s |
| 字母汤罐入篮 | 10 | 否 | 280 | 28 | 16.51 s |
| 字母汤罐入篮 | 20 | 是 | 159 | 8 | 7.04 s |

| 打开中间抽屉 | 20 | 是 | 196 | 10 | 8.42 s |

这 12 条轨迹显示：K 增大时，每个 episode 的模型调用次数明显下降，但任务步数和是否成功没有单调关系。例如 Object 和 Goal 的 K=10 在这次初态下失败，而 K=20 成功。由于每格只有一次、且只选了三个任务，不能从表中估计各 K 的总体成功率，也不能声称 K=20 总体优于 K=10。合适的展示方式是让访客切换同任务下的四段视频，观察何时因持续执行旧预测而偏离、何时重新推理。

`rollout_wall_s_with_video` 从环境 reset 前计时，到 episode 结束，包括相机帧采集、MP4 写入和同步仿真。顺序为每个任务内 K=1、5、10、20，因此还受冷启动和运行顺序影响。它能说明本次实验的调用负担，不是可直接迁移到真机的控制频率或严格性能基准。项目二的性能测量另有计时边界和重复运行。

本机原始目录：`runs/action-horizon-showcase/20261120-184139-690317/`，其中 `manifest.json` 保存逐格结果，`<suite>_0/k<K>/episode.mp4` 保存视频；目录被 Git 忽略。可提交的小型索引 [evidence.json](evidence.json) 给出每段视频的大小、SHA256、帧数及本机相对路径。12 段均可解码为 512×256、20 fps，且帧数等于环境步数加 1。复现实验入口与方法见[运行手册](../../runbooks/action-horizon-showcase.zh-CN.md)。GitHub Pages 展示页位于 `docs/index.html`，其 12 个精选 MP4 在 `docs/showcase/videos/`，由 `tools/build_action_horizon_site.py` 按 `evidence.json` 的 SHA256 验证后复制，并生成海报帧与展示数据。此公开展示视频集约 8.6 MB，是用户明确要求的网页素材；完整本机运行目录及其他大资产继续不提交到 Git。
